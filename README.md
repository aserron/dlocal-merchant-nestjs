A modern **NestJS + React TypeScript Monorepo** re-engineering the original **2018/05/17 dLocal Payment Gateway Technical Challenge**.

This project takes the original distributed payment processing premise—originally specified for Java 8, Spring 5, Embedded Jetty, Maven, and MySQL—and rebuilds it from the ground up on a modern **Node.js / TypeScript / NestJS (Fastify) + React** stack, followed by five production-grade engineering extensions.

---

## 1. Project Premise & Baseline Specification

The baseline challenge consists of two decoupled REST microservices and an automated background clearing batch process:

1. **Merchant Service (`apps/merchant`)**:
   - **`GET /check/:merchant_id`**: Verifies merchant existence (`200 OK` if found, `404 Not Found` otherwise).
2. **Payment Manager — PM Service (`apps/pm`)**:
   - **`POST /sale`**: Registers a sale in the database (`status = PENDING`), validates `merchant_id` via the Merchant Service `CHECK` endpoint, converts the original currency `amount` to `USD` via `fixer.io` (enforcing at most **1 external call every 30 seconds**), and guarantees strict idempotency on the `(merchant_id, transaction_id)` tuple by returning the same platform-unique autogenerated `id`.
   - **`GET /status/:id`**: Queries transaction metadata (`id`, `date`, `transaction_id`, `merchant_id`, `amount_usd`, and `status`: `PENDING | PAID | REJECTED`).
   - **`GET /balance?merchant_id={id}&from={date}&to={date}`**: Returns accumulated USD totals (`total_paid`, `total_pending`, `total_rejected`) for a merchant within a date range.
   - **30-Second Clearing Batch Job**: Scheduled background job executing every 30 seconds that transitions all `PENDING` transactions to `PAID` (70% probability) or `REJECTED` (30% probability).

## 2. Modern Monorepo Stack & Architecture

| Concern | Original 2018 Premise | Modern Monorepo Stack (`dlocal-merchant-nestjs`) |
| :--- | :--- | :--- |
| **Workspace & Build** | Maven Multi-Module | `pnpm` Workspaces Monorepo |
| **Backend Runtime & Framework** | Java 8 + Spring Framework 5 | Node.js 22 LTS + TypeScript 5.x + NestJS 11 |
| **HTTP Engine** | Embedded Jetty | Fastify (`@nestjs/platform-fastify`) |
| **Database & Persistence** | MySQL 5.x + JPA/Hibernate | MySQL 8 + TypeORM / MikroORM (`BINARY(16)` UUIDv7) |
| **Frontend / Operations UI** | None | React 19 + Vite / Next.js + Tailwind CSS (`apps/admin-panel`) |
| **Client Integration** | Raw REST calls | Isomorphic TypeScript SDK (`packages/client-sdk`) |
| **Testing & Load Simulation** | JUnit + MockMvc | Vitest + Supertest + Multi-Actor Load Simulator (`packages/load-simulator`) |

## 3. Beyond the Baseline: Production-Grade Extensions

In addition to fulfilling the 2018/05/17 technical specification in **Phase 1**, this repository implements five advanced capabilities:

1. **Synthetic Data Generation for Seeding (`packages/seeder`)**:
   - Deterministic `@faker-js/faker` seeding with Pareto (80/20) merchant volume tiers, realistic emerging-market currency corridors (`BRL`, `MXN`, `ARS`, `CLP`, `COP`, `UYU`, `EUR`, `USD`), time-series checkout seasonality, and streaming UUIDv7 `BINARY(16)` bulk inserts.
2. **Synthetic Usage Simulator (`packages/load-simulator`)**:
   - Five concurrent actor personas (Normal Checkout, Double-Click Network Retry bursts, Settlement Status Poller, CFO Balance Auditor, and Payload Tampering/Fault Actor) with automated post-run invariant checks.
3. **Resiliency & Circuit Breakers (`packages/resiliency`)**:
   - Outbound circuit breakers, hard timeouts, jittered retries, connection pool bulkheads, L1/L2 read-through cache fallback for Merchant `CHECK`, stale-while-revalidate fallback for `fixer.io`, and `FOR UPDATE SKIP LOCKED` non-blocking batch clearing.
4. **Solid Idempotency Engine, Client SDK & Auth Flows (`packages/client-sdk`)**:
   - Dedicated `idempotency_records` state machine with RFC 8785 canonical SHA-256 payload fingerprinting (`422 Unprocessable Entity` on mutated retries), in-flight lock + Redis Pub/Sub resolution (`409 Conflict` + `Retry-After`), HMAC-SHA256 request signing, and a client-side TypeScript SDK.
5. **React Admin Panel (`apps/admin-panel`)**:
   - Real-time operational dashboard featuring live microservice topology, manual circuit breaker overrides, transaction & balance metrics, 30s batch job & FX cache controllers, idempotency lease inspector, interactive load simulator studio, and Node.js/MySQL runtime internals.
